# Lưu / đọc save

> Một phần tài liệu project. Mục lục và quy tắc chung: `CLAUDE.md` ở thư mục gốc. Các tham chiếu "mục X" / "xem X" tra tên mục trong `docs/index.md` (mục lục chi tiết).

## Lưu / đọc save (đã chốt)

- **Mục tiêu:** tắt app bất cứ lúc nào, copy vào USB, mang sang máy khác chơi tiếp.
- **Thư mục save (portable):** ưu tiên `saves/` **cạnh file chạy game** (copy cả thư mục game vào USB là mang theo cả save). Thứ tự hiện tại: `MCC_SAVE_DIR` (chỉ dùng khi test) → `PORTABLE_EXECUTABLE_DIR/saves` (bản portable của electron-builder) → thư mục chứa file chạy (bản đóng gói) / thư mục project (dev) → không ghi được (ví dụ Program Files) thì `userData/saves` của hệ điều hành. **Sẽ đổi theo từng kiểu bản build** (bộ cài, Linux, macOS), xem "Build & phát hành". `saves/` nằm trong `.gitignore` và bị loại khỏi bản đóng gói (`electron-builder.yml`).
- **Cấu trúc:** `saves/<gameId>/auto-1.json .. auto-3.json` (**3 file tự lưu xoay vòng**, ghi đè file có `savedAt` cũ nhất) + `manual-<thời điểm ms>.json` (**lưu tay không giới hạn**, mỗi lần bấm Lưu là một file mới, xóa được). **Số game không giới hạn**; game mới không đè game cũ. `gameId` dạng `g-<base36 thời gian>-<base36 ngẫu nhiên>`.
- **File save** là JSON: `{ format: "my-creature-collector-save", gameId, kind: "auto" | "manual", savedAt (ISO), summary, state }` (sẽ thêm `appVersion`, xem "Build & phát hành"). `state` là `GameState` (nguyên liệu, không có chỉ số đã tính). `summary` chỉ để hiện danh sách; khi load luôn tính lại. **`summary` không chứa chữ hiển thị** (mục "Chữ nội dung" ở `data.md`), chỉ id và số: `{ leaderNickname (null nếu không có biệt danh), leaderSpeciesId, highestLevel, partySize, totalMonsters, money (chuỗi số), location: { type: 'town' } | { type: 'floor', floor, biomeId }, inBattle }`; UI dịch khi hiển thị, đổi ngôn ngữ không ảnh hưởng save. Main đọc summary qua `parseSaveSummary` (`game/save.ts`): sai dạng hoặc dạng cũ (trước bước 3.3, có `leaderName` / `locationName`) thì coi như không có summary (danh sách hiện `gameId`) cho tới lần lưu sau. Không đổi cấu trúc `GameState` nên không tăng version.
- **Khi nào lưu:** **tự lưu sau mỗi action ngoài trận** (sau khi tạo game và mọi `commit` có `state.battle === null`).
- **Tự rời trận khi trận kết thúc** (đã chốt, làm cùng màn trận đấu): ngay khi một action đưa trận sang `phase: 'ended'` (thắng, thua, chạy), renderer gọi tiếp `leaveBattle` và `commit` state đó, nên state được **tự lưu ngay** với thưởng, đồ rơi, quái vừa bắt, trứng nở đã áp vào. Log và kết quả trận được giữ trong bộ nhớ UI (lấy từ state trước `leaveBattle`) để hiện màn tổng kết. Tắt app ở màn tổng kết không mất gì. Core giữ nguyên action `leaveBattle`. **Trong trận không lưu** → tắt app giữa trận thì mở lại ở **trước khi vào trận**. Không tự lưu ngay khi vừa load. **Lưu tay** (nút Lưu, bị khóa khi đang trong trận) để tạo điểm quay lại.
- **Load:** `parseSave` (JSON → kiểm tra format / gameId / kind / savedAt → `migrateState` → `validateGameState` → `unequipIneligible`: món unique quái không còn lắp được tự về túi, trả `unequipped` để UI báo, mục "Trang bị và đồ cầm" ở `equipment.md`), rồi **đổi seed** (`reseedState` với seed mới từ `crypto`): load lại rồi làm cùng action sẽ ra **kết quả khác** (reroll được). Core vẫn tất định vì state sau khi đổi seed đã khác.
- **Save lỗi:** JSON hỏng, sai định dạng, save của bản game mới hơn, state không hợp lệ → hiện danh sách lỗi, **không crash, không ghi đè**.
- **Ghi an toàn:** ghi ra `<file>.tmp` rồi đổi tên đè lên file chính (tắt app / mất điện giữa lúc ghi không làm hỏng save cũ). Bản sao lưu chính là các file tự lưu xoay vòng.
- **Chuyển đổi `Decimal` khi lưu** (đã làm, save `version: 7`): file save lưu mọi trường `Decimal` thành **chuỗi** (`Decimal.toString()`, ví dụ `"1.2345e+40"`, `"1e+1000000"`). `serializeState` (`game/save.ts`) đổi mọi `Decimal` trong state thành chuỗi trước khi ghi. Khi đọc: `parseSave` → `migrateState` (nâng version; bước v6 → v7 đổi các trường số cũ sang chuỗi; bước cuối `deserializeState` đổi chuỗi số thành `Decimal`) → `validateGameState`. `deserializeState` không ném lỗi: chuỗi không đọc được (`"NaN"`, `"Infinity"`, `"abc"`), `null` hay number ở save v7 được giữ nguyên để `validateGameState` báo lỗi kèm đường dẫn trường. Vị trí các trường `Decimal`: danh sách duy nhất trong `game/bigFields.ts` (xem mục "Số lớn"). `summary.money` trong file là chuỗi; renderer hiển thị bằng `formatNumber`.
- **Kiểm tra số trong `validateGameState`** (`src/core/game/validateGameState.ts`; `validateMonster(data, monster, path)` nhận thêm đường dẫn để ghi vào thông báo): trường `Decimal` (`money`, `exp`, `damageTaken`, `genes`, `fusingBonusStats`) phải là `Decimal` hữu hạn ≥ 0 (`genes` ≥ 1) qua `checkBig`. Trường còn là `number` (`level`, `shinyStacks`, `bossMultiplier`, `traitSlots`, `rng`, `nextMonsterId`, số lượng vật phẩm, `battlesLeft` của trứng, bậc trận...) phải qua `Number.isFinite`; trường nguyên qua thêm `Number.isSafeInteger` (≤ 2^53 − 1). Kiểm tra cả quái trong đội, kho, trứng, và trong trận (`enemies`, `captured`). Gặp `Infinity`, `NaN`, `null` thay cho số, hoặc sai kiểu thì là save lỗi, báo rõ đường dẫn trường (ví dụ `party[0].genes.attack`). Lưu ý `JSON.stringify(Infinity)` ra `null` nên phải bắt được `null`.
- **Test số cực lớn cho save** (`validateGameState.test.ts`, `migrate.test.ts`):
  - `validateGameState` từ chối: `money` là `Decimal` Infinity / -Infinity / NaN / âm, number (chưa đổi sang `Decimal`), `null`, chuỗi; gen `Decimal` Infinity; `level = 2^53` (vượt safe integer); `damageTaken` âm; lỗi nằm sâu trong kho, trứng, quái hoang và quái đã bắt trong trận. Mỗi case kiểm tra đúng đường dẫn trường.
  - `validateGameState` chấp nhận số lớn hợp lệ: tiền `1e1000`, gen `1e300`, EXP `1e1000`, `fusingBonusStats` lẻ.
  - `parseSave`: chấp nhận `"1e1000"`, `"1e1000000"`, `"123.5"`; từ chối `"NaN"`, `"Infinity"`, `"abc"`, `"-5"`, `null`, `1e400` (number tràn), `100` (number ở save v7); lưu rồi đọc lại khớp giá trị kể cả `1e1000000`.
  - Migrate: save v6 (số là number, kể cả trong log trận và trứng) mở được và ra đúng state; save v6 có `null` không crash, báo lỗi.
- **Xuất / Nhập:** "Xuất save ra file" ghi state hiện tại ra file người chơi chọn (ví dụ USB). "Nhập save từ file" kiểm tra đầy đủ, lưu vào thư mục save như **một bản lưu tay của đúng game đó** (cùng `gameId` thì nối tiếp game cũ trên máy này), rồi mở luôn. File nhập lớn hơn 50 MB bị từ chối.
- **Hồ sơ xuyên save** `saves/profile.json` (cạnh các thư mục game; không phải save nên `listSaves` bỏ qua): `{ version: 1, unlockedStarterIds }` (loài khởi đầu đã mở, `starters.md`). Main chỉ đọc / ghi chữ (`src/main/saves/profile.ts`: `readProfile` trả null khi chưa có / không đọc được / > 5 MB, `writeProfile` ghi an toàn), IPC `saves:readProfile` / `saves:writeProfile`; nội dung kiểm ở core (`parseProfile`: hỏng = rỗng, không crash); renderer đọc khi mở app (`features/saves/profileService.ts`). Copy USB mang theo cùng thư mục save. Đổi cấu trúc thì tăng `PROFILE_VERSION` và đọc được bản cũ trong `parseProfile` (không đi qua `migrateState`).
- **Phân việc:** main (`src/main/saves/saves.ts`: đọc / ghi / liệt kê / xóa, chống path traversal bằng kiểm tra `gameId` và tên file; `src/main/saves/saveIpc.ts`: chọn thư mục, đăng ký IPC `saves:*`, hộp thoại Xuất / Nhập) ↔ preload (`window.api.saves`, kiểu trong `src/preload/api.d.ts`, không lộ `ipcRenderer`) ↔ renderer (`src/renderer/src/features/saves/saveService.ts`: tạo nội dung file, `parseSave`, `reseedState`; core không gọi I/O).
